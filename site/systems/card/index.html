    카드 시스템

    📄 docs/systems/card.md

    참고 문서: 게임 세부 시스템 개요 §카드 시스템, 게임 개요 §스킬 카드와 발동 조건
    관련 문서: 보드 시스템, 전투 시스템 (작성 예정)

    1. 개요

    카드 시스템은 출전 캐릭터의 스킬 카드를 대기덱·핸드덱·소모덱 세 영역으로 통합 관리하는 구조다. 각 카드에는 보드에서 소모해야 하는 발동 숫자(0·2·4·8·…·2048)가 지정되어 있으며, 숫자가 높을수록 강력한 효과를 제공한다.

    발동 숫자 0인 카드는 보드 타일을 소모하지 않으며, 퍼즐 없이 즉시 사용 가능하다.

    캐릭터마다 사용하는 카드 코스트 범위가 고정되어 있으며(§2-4), 턴에 주어지는 슬라이드 횟수는 출전 캐릭터의 고유 스탯이다. (board.md §5-1 참조)

    1-1. 캐릭터 전용 원칙

    모든 스킬 카드는 특정 캐릭터 1인의 전용 카드다. 공통 카드·공용 카드 풀은 존재하지 않는다.

    항목 규칙
    소유 모든 카드는 ownerCharacterId로 소유 캐릭터가 확정된다. 소유자 없는 카드는 없다
    덱 구성 전투 덱은 출전 캐릭터 소유 카드로만 구성된다. 미출전 캐릭터의 카드는 포함되지 않는다
    보상·상점 카드 획득 경로(전투 보상·상점·이벤트) 전부 출전 캐릭터 소유 카드만 후보로 제시한다 (§6)
    카드 이름 캐릭터 간 중복되지 않는다. 같은 역할의 카드라도 캐릭터마다 고유 이름·연출을 가진다
    강화 강화된 카드도 소유 캐릭터가 바뀌지 않는다

    이 원칙에 따라 캐릭터 선택이 곧 카드 풀 선택이 된다. 코스트 밴드(§2-4)·슬라이드 스탯과 함께, 캐릭터가 전투 경험 전체를 규정하는 축이다.

    캐릭터별 실제 카드 목록은 contents/skills.md에서 관리한다.

    카드 시스템의 흐름 요약

    전투 시작
    └─ 선택 캐릭터의 카드를 셔플 → 대기덱 구성
           └─ 5장 드로우 → 핸드덱 구성
                  ↓
           [슬라이드 페이즈] 보드에 타일 준비
                  ↓
           [카드 선택] 같은 숫자 카드 여러 장이면 원하는 카드 선택
                  ↓
           [액션 버튼]
             ├─ 매칭된 카드: 타일 소모 → 효과 발동
             └─ 미매칭 카드: 효과 없이 대기
                  ↓
           핸드 전체 소모덱으로 이동 → 대기덱에서 재드로우
                  ↓
           [반복] 전투 종료 → 보상 3장 중 1장 선택

    2. 카드 데이터 구조

    2-1. Card 구조체

    필드명 타입 설명
    id string 카드 고유 식별자 (예: "char_a_attack_01")
    name string 카드 표시 이름 (예: "참격")
    ownerCharacterId string 이 카드를 소유하는 캐릭터 ID. 소유 캐릭터 식별에 사용
    triggerNumber int 발동에 필요한 보드 타일 숫자. 허용값: 0 및 2의 거듭제곱 2~2048 (0·2·4·8·16·32·64·128·256·512·1024·2048). 0은 타일 소모 없이 발동
    grade CardGrade 발동 숫자로 결정되는 등급 열거형 (§2-3 참고)
    effectType CardEffectType 카드 효과 분류 열거형 (§2-2 참고)
    effectParams EffectParams 효과 실행에 필요한 파라미터 묶음 (§2-2 참고)

    제약 조건

    • triggerNumber는 반드시 {0, 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024, 2048} 집합에 속해야 한다.
    • triggerNumber == 0인 카드는 보드 매칭을 거치지 않고 항상 발동 가능하다. (§5-3 참조)
    • upgradedTriggerNumber가 존재하는 경우, 반드시 triggerNumber보다 작아야 한다.
    • 강화로 발동 숫자는 0까지 내려갈 수 있다. 즉 충분히 강화된 카드는 퍼즐 없이 발동하는 무코스트 카드가 된다.
    • upgradeLevel이 0이면 upgradedTriggerNumber는 null이다.
    • ownerCharacterId는 현재 전투에 출전한 캐릭터의 ID와 일치해야 한다. 미출전 캐릭터의 카드는 덱에 포함되지 않는다.

    런타임에서의 발동 숫자 결정

    effectiveTriggerNumber = (upgradeLevel >= 1 && upgradedTriggerNumber != null)
    ? upgradedTriggerNumber
    : triggerNumber

    2-2. 효과 타입 열거형 (CardEffectType)

    7종으로 확정한다. contents/skills.md의 100장이 실제로 요구하는 범위를 기준으로 산정했으며, 버프·디버프의 식별자 규약은 enemy.md §5-3·5-4와 통일한다.

    CardEffectType 설명 주요 EffectParams 필드 사용 예
    ATTACK 적에게 피해를 입힌다 damage, targetType, hitCount, ignoreShield, damageSource 방패 치기, 관통탄
    SHIELD 피해를 흡수하는 방어막을 부여한다 shieldAmount 베스천 전개, 철벽 요새
    HEAL 체력을 회복한다 healAmount, duration 나노 치유, 재생 촉진
    BUFF 자신에게 유리한 상태를 부여한다 effectId, power, duration 조준 보정, 강철 의지
    DEBUFF 적에게 불리한 상태를 부여한다 effectId, power, duration, targetType 취약 지정, 억제 필드
    UTILITY 보드·덱·적 카운트를 조작한다 utilityId, power 슬라이더, 장벽 생성, 예측 조작
    PERSISTENT 전투가 끝날 때까지 규칙 자체를 변경한다 persistentId 바리케이드

    설계 판단

    • STATUS_EFFECT는 별도 타입으로 두지 않는다. 독·마비 등은 DEBUFF의 effectId로 표현하면 충분하며, 타입을 나누면 중첩·해제 규칙이 이원화된다.
    • DRAW도 별도 타입이 아니라 UTILITY의 utilityId: "draw"로 흡수한다. 드로우는 보드·덱 조작 계열과 처리 흐름이 같다.
    • PERSISTENT는 1회 발동 후 전투 내내 유지되는 유일한 타입이다. 다른 타입은 모두 발동 즉시 해소된다.

    EffectParams 공통 구조

    EffectParams {
    targetType    : TargetType    // SELF | SINGLE_ENEMY | ALL_ENEMIES

    // ATTACK
    damage        : int?          // 1회 타격당 피해량
    hitCount      : int?          // 타격 횟수. 생략 시 1 (다단 공격용)
    ignoreShield  : bool?         // true면 방어막을 무시하고 체력에 직접 적용
    damageSource  : DamageSource? // 피해량 산출 기준. 생략 시 damage 고정값 사용
    bonusCondition: string?       // 조건부 배율. 예: "target_hp_below_30" → 피해 2배

    // SHIELD / HEAL
    shieldAmount  : int?
    healAmount    : int?          // duration 지정 시 "매 턴 healAmount 회복"

    // BUFF / DEBUFF
    effectId      : string?       // enemy.md와 공유하는 식별자 (아래 표)
    power         : int?          // 효과 강도. % 또는 절대값 (effectId별 해석)
    duration      : int?          // 지속 턴 수 (액션 버튼 횟수 기준). 0 = 영구

    // UTILITY / PERSISTENT
    utilityId     : string?
    persistentId  : string?
}

enum DamageSource {
    FIXED,           // damage 필드 값 그대로 (기본)
    CURRENT_SHIELD   // 현재 방어막 수치만큼 (몸통 박치기)
}

    targetType에 아군 대상값이 없는 것은 1인 전투이기 때문이다. 회복·버프는 항상 출전 캐릭터 자신(SELF)에게 적용되므로 대상 선택이 불필요하다. (character.md §피해 대상)

    effectId 목록 (BUFF · DEBUFF)

    enemy.md가 적 측에서 사용하는 식별자와 동일한 이름 공간을 쓴다. 같은 effectId는 주체가 누구든 같은 규칙으로 동작한다.

    power 해석 규칙 (A-8 확정) — 식별자 성격에 따라 두 가지로 나뉘며, 혼용하지 않는다.

    • 비율형(%) — 피해·획득량처럼 다른 수치에 곱해지는 효과. 발동 숫자가 0~2048로 3자릿수 이상 벌어져 있어(피해 2 ~ 1650), 절대값 증감은 저코스트에서 과하고 고코스트에서 무의미해진다. 따라서 모든 배율성 효과는 %로 통일한다.
    • 수치형(절대값) — 독 피해량, 발동 횟수처럼 그 자체가 최종 수치인 효과.
    effectId 분류 대상 설명 power
    attack_up BUFF 자신 주는 피해 증가 %
    damage_reduce BUFF 자신 받는 피해 감소 %
    shield_gain_up BUFF 자신 방어막 획득량 증가 %
    thorns BUFF 자신 받은 피해의 일부를 공격자에게 반사 %
    endure BUFF 자신 치명 피해를 체력 1로 버팀 절대값 (횟수)
    attack_down DEBUFF 적 주는 피해 감소 %
    defense_down DEBUFF 적 방어막 획득량 감소 %
    vulnerable DEBUFF 적 받는 피해 증가 %
    taunt DEBUFF 적 다음 행동을 반드시 캐릭터에게 사용 —
    poison DEBUFF 적 액션 버튼마다 체력 감소 절대값 (피해)

    enemy.md §5-3·5-4의 attack_down·attack_up은 원래 절대값 해석이었으나, 위 규칙에 맞춰 %로 통일했다. 적이 부여하든 카드가 부여하든 같은 effectId는 완전히 동일하게 동작한다.

    중첩 규칙 (A-9 확정)

    같은 effectId가 여러 번 부여될 때의 처리다.

    항목 규칙
    power 합산한다. 단 effectId별 상한에서 멈춘다
    duration 더 긴 쪽으로 갱신한다 (max). 합산하지 않는다
    상한 도달 후 power는 더 오르지 않고 duration만 갱신된다
    서로 다른 effectId 각각 독립적으로 유지된다 (예: vulnerable와 defense_down 동시 적용)

    합산을 택한 이유 — 사이퍼는 디버프 특화 캐릭터로 해킹 패킷(+15%)·취약 지정(+30%) 등 같은 계열 카드를 여러 장 가진다. 갱신 방식이면 낮은 카드가 높은 카드 뒤에 나오는 순간 완전히 무의미해져 덱 구성의 의미가 사라진다. 합산은 "겹칠수록 강해지는" 디버프 특화의 정체성을 지탱한다.

    상한이 필요한 이유 — 무제한 합산 시 지속 턴 안에 디버프를 계속 덧씌워 피해 배율이 발산한다. 상한은 그 폭주를 막는 안전장치다.

    effectId 상한
    vulnerable +100% (받는 피해 최대 2배)
    attack_up +100%
    attack_down −60%
    defense_down −60%
    damage_reduce −50%
    shield_gain_up +100%
    thorns +50%
    endure 3회
    poison 상한 없음 (절대값 누적)

    피해 계산식

    버프·디버프가 모두 반영된 최종 피해량이다. 각 항의 %는 중첩 합산 후 상한이 적용된 값이다.

    최종 피해 = 기본 피해
          × (1 + 공격자.attack_up% − 공격자.attack_down%)   ← 공격자 측 보정
          × (1 + 대상.vulnerable%)                          ← 대상 피격 증폭
          × (1 − 대상.damage_reduce%)                        ← 대상 경감

→ 방어막이 있으면 방어막부터 차감, 초과분을 체력에 적용
   (ignoreShield = true면 방어막을 건너뛰고 체력에 직접)
    • 각 괄호는 곱연산, 괄호 안 동종 효과는 합연산이다.
    • 계산 결과가 음수면 0으로 클램프한다.
    • defense_down은 피해가 아니라 방어막 획득 시점에 적용된다: 실제 방어막 = 표기값 × (1 + shield_gain_up% − defense_down%)

    utilityId 목록

    utilityId 설명 power 해석
    draw 대기덱에서 즉시 드로우 드로우 장수
    slide_plus 이번 턴 슬라이드 횟수 증가 증가 횟수
    tile_lock 보드 타일 1개를 이동 불가로 고정 고정 턴 수
    tile_move 타일 1개를 지정 빈 칸으로 이동 —
    tile_merge 타일 1개를 인접 타일과 즉시 병합 —
    tile_purify 방해 타일 제거 제거 개수
    enemy_count_up 적 행동 카운트 증가 증가값
    cleanse 자신의 디버프 제거 제거 개수. 0 = 전부
    summon_drone 드론 배치. 지속 턴 동안 매 턴 자동 공격 공격력
    reveal_intent 적의 다음 행동을 미리 표시 —

    persistentId 목록

    persistentId 설명
    barricade 방어막을 소모하는 효과(damageSource: CURRENT_SHIELD)가 방어막을 소모하지 않게 한다

    duration의 단위는 액션 버튼 횟수 기준이며, enemy.md 미결 C-5와 규약을 공유한다.

    2-3. 카드 등급 정의 (CardGrade)

    카드 등급은 triggerNumber로 결정되며, 강화 후 upgradedTriggerNumber가 기존 등급 경계를 넘어서도 기준 등급은 변경되지 않는다. 등급은 카드 식별 및 UI 표시 목적으로만 사용한다.

    등급 구간은 2048까지 확장 가능한 체계로 정의한다. 상위 등급이 추가되어도 아래 구간 정의를 유지한 채 확장한다.

    CardGrade 값 triggerNumber 등급명 효과 규모 예시
    FREE 0 무코스트 타일 소모 없이 발동. 소량 유틸·드로우
    BASIC 2 · 4 기본 단일 약공격, 소량 방어막
    NORMAL 8 · 16 일반 단일 공격, 디버프 1개
    ENHANCED 32 · 64 강화 중간 공격, 광역 디버프, 회복
    POWERFUL 128 · 256 강력 강한 광역 공격, 방어막
    LETHAL 512 · 1024 필살 캐릭터 전용 필살기
    TRANSCENDENT 2048 초월 전투 판도를 뒤집는 초강력 효과

    2-4. 발동 숫자와 캐릭터 코스트 밴드

    캐릭터마다 사용하는 카드 코스트 범위가 고정되어 있다. 임의의 캐릭터가 임의의 숫자 카드를 갖지 않으며, 밴드 상한이 그 캐릭터의 슬라이드 스탯과 짝을 이룬다.

    캐릭터 코스트 밴드 슬라이드 스탯 필요 2-타일 (상한 N/2) 한 턴 내 상한 완성
    주베 0 ~ 64 30 32 ✗
    사이퍼 0 ~ 128 60 64 ✗
    펄스 0 ~ 256 120 128 ✗
    케스트럴 0 ~ 512 260 256 ✓
    베인 4 ~ 1024 520 512 ✓

    슬라이드 스탯은 대략 밴드 상한의 절반(N/2)으로 설정된다. 값 2 타일로 숫자 N을 만들려면 N/2개의 타일이 필요하고 슬라이드 1회당 타일 1개가 생성되기 때문이다.

    주베·사이퍼·펄스는 상한 카드를 한 턴에 완성할 수 없어 턴을 넘겨 쌓아야 하고, 케스트럴·베인은 한 턴에 몰아서 완성할 수 있다. 보드가 턴을 넘어 유지되므로 전자도 성립하며, 이 차이가 캐릭터별 운영 감각을 만든다.

    상세: character.md §슬라이드 스탯 · board.md §5-1

    3. 덱 운영 구조

    3-1. DeckState 구조체

    전투 중 카드 전체의 상태를 표현하는 구조체다. 전투 시작 시 초기화되고, 전투 종료 시 소멸한다.

    DeckState {
    waitDeck    : Card[]    // 대기덱 — 드로우되지 않은 카드들. 셔플된 순서로 관리
    hand        : Card[]    // 핸드덱 — 현재 사용 가능한 카드들. 최대 5장
    discardDeck : Card[]    // 소모덱 — 발동·미발동 모두 포함해 버려진 카드들. 순서 유지
}

    [미결 A-5] 덱 전체 카드 수의 상한이 결정되지 않았습니다.
    - (a) 상한 없음 — 전투 보상으로 카드를 계속 추가할 수 있음
    - (b) 최대 N장 제한 — 상한 초과 시 기존 카드를 제거하거나 추가를 거부하는 규칙 필요

    소모덱 순환 주기와 전략적 덱 설계에 직접 영향을 줍니다. (a) 채택 시 DeckState에 상한 필드 불필요. (b) 채택 시 maxDeckSize: int 필드 추가 필요.

    3-2. 세 영역의 역할

    영역 구조체 필드 역할 드로우 가능 여부
    대기덱 (waitDeck) Card[] 아직 드로우되지 않은 카드 풀. 셔플된 상태로 유지되며 맨 앞 카드부터 드로우됨 O
    핸드덱 (hand) Card[] 현재 플레이어가 운용 중인 카드. 액션 버튼 발동의 대상이 되는 영역 X
    소모덱 (discardDeck) Card[] 사용 후 버려진 카드. 대기덱이 소진되면 전체 셔플 후 대기덱으로 전환됨 X (직접 접근 불가)

    3-3. 영역 간 이동 규칙

    아래 표는 카드가 한 영역에서 다른 영역으로 이동하는 모든 시점과 조건을 정의한다.

    이동 방향 트리거 조건 비고
    대기덱 → 핸드덱 드로우 대기덱에 1장 이상 존재 맨 앞 카드를 꺼내 핸드덱 끝에 추가
    소모덱 → 대기덱 셔플 대기덱이 0장이고 드로우가 필요한 시점 소모덱 전체를 무작위 순서로 재배열 후 대기덱으로 전환
    핸드덱 → 소모덱 액션 버튼 이후 핸드에 카드가 존재 발동 여부와 무관하게 핸드 전체 이동. 이동 순서는 핸드 내 인덱스 순서

    3-4. 전투 시작 초기화 순서

    1. 출전 캐릭터의 카드를 전부 수집
2. 수집된 카드 전체를 waitDeck에 배치
3. waitDeck을 무작위 순서로 셔플
4. waitDeck에서 최대 5장 드로우 → hand에 배치
   └─ 드로우 상세 규칙은 §4 드로우 규칙 참고
5. discardDeck은 빈 배열로 초기화

    4. 드로우 규칙

    4-1. 드로우 트리거 2종

    드로우는 다음 두 시점에만 발생한다.

    트리거 시점 목표 드로우 수
    전투 시작 드로우 전투 초기화 완료 직후 (§3-4 4번 단계) 5장
    액션 버튼 이후 드로우 핸드 전체가 소모덱으로 이동한 직후 5장

    두 트리거 모두 동일한 드로우 함수(drawCards(count: 5))를 호출한다.

    4-2. 드로우 함수 동작 (drawCards(count))

    function drawCards(count: int):
    remaining = count

    while remaining > 0:
        if waitDeck.length == 0:
            if discardDeck.length == 0:
                break  // §4-4 예외 처리 적용
            else:
                shuffleDiscardIntoDeck()  // §4-3 셔플 처리

        card = waitDeck.shift()  // 맨 앞 카드 꺼내기
        hand.push(card)
        remaining -= 1

    4-3. 대기덱 소진 시 셔플 처리

    [미결 A-3] 셔플 타이밍이 확정되지 않았습니다.
    - (a) 대기덱이 0장이 되는 순간 즉시 셔플 — 드로우 필요 여부와 무관하게 소진과 동시에 셔플
    - (b) 드로우를 시도하는 시점에 대기덱이 0이면 그때 셔플 — 표준적인 TCG 방식

    현재 문서는 (b) 기준으로 작성되어 있습니다. (a) 채택 시 drawCards 함수 외부에 소진 감지 훅 추가 필요.

    shuffleDiscardIntoDeck() 처리 순서:

    1. discardDeck 전체를 waitDeck으로 이동
2. waitDeck을 무작위 순서로 셔플
3. discardDeck을 빈 배열로 초기화

    4-4. 전투 시작 드로우 시 대기덱 5장 미만 처리

    [미결 A-2] 전투 시작 시 대기덱이 5장 미만인 경우의 처리가 확정되지 않았습니다.
    - (a) 있는 장수를 먼저 드로우한 뒤, 소모덱을 셔플하여 대기덱을 보충하고 나머지를 드로우
    - (b) 있는 장수만 드로우하고 셔플 없이 전투 시작 (핸드가 5장 미만인 채로 시작 가능)

    전투 시작 시 소모덱은 빈 상태(§3-4 5번)이므로, 대기덱이 5장 미만인 상황은 전투 보상으로 카드 수가 적은 초반에만 발생합니다. (a)는 사실상 초반에 효과가 없으며 (b)와 동일하게 동작합니다. 이 시나리오 자체가 발생 불가능한지 최소 덱 구성 규칙으로 방지할 것인지도 함께 결정 필요.

    4-5. 예외: 대기덱·소모덱 모두 0장

    drawCards 함수 내에서 waitDeck.length == 0이고 discardDeck.length == 0이면 드로우를 중단한다.

    • 핸드덱은 현재까지 드로우된 장수만큼만 유지된다 (0장일 수 있음).
    • 0장 핸드 상태에서도 액션 버튼은 눌를 수 있다. 발동되는 카드가 없으므로 효과 없이 핸드 교체(이미 비어있음) → 적 카운트 -1만 처리된다.
    • 이 상태는 덱이 매우 작고 순환이 완료된 경우에 발생한다.

    5-2. 중복 숫자 카드 선택

    핸드에 동일한 effectiveTriggerNumber를 가진 카드가 여러 장 존재하고, 보드에 해당 숫자 타일이 존재할 때 선택이 필요하다.

    [미결 B-3] 중복 숫자 카드 선택 UI의 발동 시점이 확정되지 않았습니다.
    - (a) 액션 버튼을 누르기 전에 핸드 영역에서 항상 원하는 카드를 선택할 수 있는 상태 유지
    - (b) 액션 버튼을 누른 뒤 중복이 감지된 시점에 선택 팝업 표시

    (a)는 사전 계획을 강조하는 방식으로 UX가 자연스럽습니다. (b)는 구현이 단순하지만 플레이어가 액션 버튼 이후 추가 입력을 해야 하는 흐름이 됩니다.

    중복 검사 로직:

    boardHasTile = board.hasTile(uniqueTriggerNumber)

    if candidates.length > 1 && boardHasTile:
        // 선택 UI 표시 → 플레이어가 1장 선택
        // 나머지 candidates는 미선택 상태가 되어 매칭에서 제외
        // (단, 보드에 같은 숫자 타일이 2개 이상이면 여러 장 발동 가능 — §5-3 참고)

    5-3. 매칭 검사

    핸드의 각 카드에 대해 보드에서 effectiveTriggerNumber와 일치하는 타일을 찾는다.

    규칙:

    • effectiveTriggerNumber == 0인 카드는 매칭 검사를 건너뛰고 항상 발동 대상에 포함한다. 소모할 타일이 없으므로 보드 상태와 무관하게 발동하며, 보드가 비어 있거나 슬라이드 불능이어도 영향받지 않는다.
    • 0 이외의 카드는 정확한 숫자 일치만 허용한다. 더 높은 숫자 타일로 대체 발동은 불가.
    • 보드에 같은 숫자 타일이 여러 개 있으면, 핸드에 같은 숫자 카드가 여러 장일 때 각각 다른 타일을 소모하여 복수 발동이 가능하다.

    타일 소모 위치 선택:

    [미결 B-2] 보드에 같은 숫자 타일이 여러 개일 때 소모할 타일 위치 결정 방식이 확정되지 않았습니다.
    - (a) 자동 선택 — 보드 좌상단 → 우하단 방향으로 첫 번째 해당 타일을 소모
    - (b) 플레이어가 직접 소모할 타일 위치를 선택 (추가 선택 UI 필요)

    (b)는 전략적 깊이를 높이지만 조작 복잡도가 증가합니다.

    매칭 후 타일은 즉시 보드에서 제거한다. 이후 카드 효과 실행(§5-4) 순서와 관계없이, 타일 소모는 매칭 검사 완료 시점에 일괄 처리한다.

    5-4. 효과 실행 순서

    [미결 B-1] 매칭된 카드의 효과 실행 순서가 확정되지 않았습니다.
    - (a) 핸드에서 낮은 인덱스(왼쪽) 순서대로 실행
    - (b) effectiveTriggerNumber 오름차순 (낮은 숫자 먼저)
    - (c) effectiveTriggerNumber 내림차순 (높은 숫자 먼저)
    - (d) 플레이어가 실행 순서를 직접 지정

    효과 실행 중 캐릭터 체력이 0이 되어도 현재 카드의 효과는 완전히 적용된 후 전투 결과를 판정한다.

    5-5. 미매칭 카드 처리

    매칭에 실패한 카드(보드에 해당 타일 없음)는 효과를 발동하지 않는다. 이 카드들은 매칭된 카드와 함께 핸드 교체 시 소모덱으로 이동한다.

    핸드 교체 처리:

    1. hand 내 모든 카드(매칭·미매칭 모두 포함)를 discardDeck으로 이동
2. hand를 빈 배열로 초기화
3. drawCards(5) 호출 (§4-2)

    6. 카드 보상 및 덱 관리

    7-1. 전투 보상 흐름

    전투 승리 시 카드 보상 선택 화면이 표시된다.

    전투 승리 확정
    ↓
보상 후보 카드 3장 무작위 선정
  (출전 캐릭터 전용 카드 풀에서만 추출 — §1-1)
    ↓
보상 화면 표시: 카드 3장을 나란히 표시, 각 카드의 이름·발동 숫자·효과 표시
    ↓
플레이어가 1장 선택
    ↓
선택한 카드를 현재 덱(waitDeck 또는 discardDeck)에 추가
    └─ 추가 위치: discardDeck 끝에 추가 (즉시 핸드에 올라오지 않음)
    ↓
보상 화면 종료 → 거점 귀환

    보상 후보 카드 3장은 현재 덱에 포함된 카드와 중복될 수 있다. 단, 후보는 출전 캐릭터가 소유한 카드(ownerCharacterId 일치)로만 구성된다. 다른 캐릭터의 카드는 어떤 경로로도 보상에 등장하지 않는다. (§1-1 캐릭터 전용 원칙)

    보상 화면에서 카드를 선택하지 않고 건너뛰는 옵션은 별도로 결정 필요 (현재 미정의).

    7-2. 챕터 클리어 시 덱 초기화

    챕터 클리어 확정 시점에 아래 순서로 초기화한다.

    1. DeckState 전체(waitDeck, hand, discardDeck) 소멸
2. 전투 보상으로 획득한 카드 전부 제거
3. 강화된 카드(upgradeLevel >= 1)도 제거
4. 챕터 시작 이전의 기본 덱 구성으로 복원

    기본 덱의 정의(캐릭터별 초기 카드 목록, 초기 장수)는 contents/skills.md §기본 스킬덱에서 관리한다.

    7-3. 거점에서의 덱 편집

    거점 귀환 후 다음 챕터 진입 전, 플레이어는 덱 편집 화면에서 아래 작업을 수행할 수 있다.

    작업 가능 여부 비고
